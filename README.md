# plug-dbt

A Snowflake dbt exercise scaffold for the deterministic four-source synthetic
EV marketplace generated by `plug-tech-screen`.

## Implemented graph

| Seed | Physical rows | Grain |
| --- | ---: | --- |
| `raw_valuation_requests` | 2,000 | One immutable request delivery |
| `raw_vehicle_assessments` | 1,916 | One assessment-version or unsupported-envelope delivery |
| `raw_offer_events` | 3,391 | One claimed immutable offer-event delivery |
| `raw_marketplace_events` | 2,951 | One typed immutable marketplace-event delivery |

Every seed column loads as Snowflake `VARCHAR` with unquoted lower-snake-case
identifiers. The four incremental append `stg_*` models retain every raw field
and add a deterministic `delivery_sk`, parsed `TIMESTAMP_TZ` values, exact
numeric derivatives, explicit unit normalization, and warning flags.

The four source-specific `int_*_dispositions` views derive supported-schema
checks, immutable-key replay handling, deterministic survivor pointers,
request/VIN relationships, pricing-assessment availability, and supported
marketplace transitions at runtime. `int_delivery_dispositions` provides the
common interface, and four `int_canonical_*` views expose accepted survivors.

`fct_vehicle_lifecycle` is intentionally absent as the candidate exercise.

## Configure an isolated target

Use a pre-created, non-production Snowflake schema. The profile fallback is
`DBT_MIGRATION`, but set `DBT_SNOWFLAKE_SCHEMA` explicitly before warehouse
work so the isolated target is unambiguous.

```sh
cp .env.example .env
cp profiles.yml.example ~/.dbt/profiles.yml

set -a
source .env
set +a
```

Never commit `.env` or print secret environment-variable values.

## Validate the handoff

The CSVs came byte-for-byte from clean `plug-tech-screen` commit
`24fc26b1539754f15c18e9f8fc43f200f55ecc49`.

```sh
python3 scripts/validate_seed_handoff.py \
  --source-dir ../plug-tech-screen/data
```

The validator checks exact filenames, headers, row counts, encoding, quoting,
timestamps, ordering, cutoff, physical keys, byte equality, and every column's
nulls, distinct values, ranges, and bounded categorical frequencies.

## Scoped dbt workflow

Inspect selectors before warehouse mutation:

```sh
dbt parse
dbt ls --select "resource_type:seed" --output name
dbt ls --select "stg_valuation_requests stg_vehicle_assessments stg_offer_events stg_marketplace_events" --output name
dbt ls --select "int_valuation_request_dispositions int_vehicle_assessment_dispositions int_offer_event_dispositions int_marketplace_event_dispositions int_delivery_dispositions" --output name
```

After confirming the isolated development target:

```sh
dbt debug
dbt seed --select "raw_valuation_requests raw_vehicle_assessments raw_offer_events raw_marketplace_events"
dbt build --select "stg_valuation_requests stg_vehicle_assessments stg_offer_events stg_marketplace_events"
dbt build --select "int_valuation_request_dispositions int_vehicle_assessment_dispositions int_offer_event_dispositions int_marketplace_event_dispositions"
dbt build --select "int_delivery_dispositions"
dbt build --select "int_canonical_valuation_requests int_canonical_vehicle_assessments int_canonical_offer_events int_canonical_marketplace_events"
```

Do not run an unscoped build, production command, direct Snowflake DDL, or
`--full-refresh` without explicit approval.

## Candidate lifecycle contract

The future `models/core/fct_vehicle_lifecycle.sql/.yml` pair must have exactly
one row per `request_id` and expose this 13-column handoff contract:

1. `request_id`
2. `selected_assessment_id`
3. `selected_assessment_version`
4. `offer_id`
5. `offer_version`
6. `pricing_evaluation_id`
7. `auction_id`
8. `winning_bid_id`
9. `buyer_dealer_id`
10. `transaction_id`
11. `pricing_label_status`
12. `terminal_stage`
13. `dropoff_reason`

The candidate owns point-in-time assessment selection, current offer-version
selection, marketplace reconstruction, request-grain fan-in, lifecycle and
label classification, focused tests, reconciliation, and bounded analysis.
